# KiraAI History Plugin/跨会话历史与总结

> 提供工具让 AI 可以跨会话获取群聊/私聊消息历史并总结，**支持按时间段 / 用户 / 关键词定位查询**，
> 兼容 NapCat / LLOneBot / SnowLuma 三种 OneBot 实现。

## 这是什么？

让机器人能查看指定群聊或私聊的聊天记录，用于总结、分析、转发等场景。支持图片 URL、消息 ID 等完整信息。

两种用法：**只给条数**取最近 N 条；**给条件**（时间 / 用户 / 关键词）则从最新消息往回翻页查找。

## 特性

- ✅ **跨实现兼容**：NapCat / LLOneBot / SnowLuma 都能稳定获取真实历史
- ✅ **双通道**：WS 通道优先（与适配器同一 ID 命名空间，get_msg 可反查），HTTP 通道兜底
- ✅ **强解析**：引用消息显示 `[引用 msg_id:xxx]`，图片带真实 URL，不再出现 `[引用消息]` 占位
- ✅ **自动过滤**：无法解析的空引用占位消息自动过滤，不污染 LLM 上下文
- ✅ **get_msg 刷新**：媒体源缺失的消息自动调 get_msg 刷新（SnowLuma 会刷新图片 URL）
- ✅ **定位查询**：按时间段 / 用户 / 关键词查找历史，从最新往回翻页并本地过滤
- ✅ **诚实报告**：每次定位返回「命中 / 扫描 / 覆盖时间 / 是否到最早」，未命中时明确说明是「扫描范围内未找到」
- ✅ **防循环**：查询签名缓存、子集拒绝、每回合扫描量预算、失败熔断、递减重试拦截
- ✅ **权限控制**：主人全权限，普通用户只能看自己的私聊和非限制群聊

## 安装

1. 安装依赖：`pip install httpx`
2. OneBot 程序开启 HTTP 服务（默认端口 3000），确认 token
3. 复制 `history_plugin` 文件夹到 `data/plugins/`
4. WebUI 中配置主人账号

## 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `http_host` | string | `localhost` | OneBot HTTP 服务地址 |
| `http_port` | integer | `3000` | OneBot HTTP 端口 |
| `access_token` | string | 空 | OneBot 设置的访问令牌 |
| `use_ws` | switch | `true` | 优先使用适配器 WS 通道（推荐开启，ID 与转发/撤回一致）；关闭则仅用 HTTP |
| `master_id` | string | 空 | 主人 QQ 号，拥有所有权限 |
| `allowed_users` | string | 空 | 其他允许使用的用户 QQ，逗号分隔 |
| `restricted_groups` | string | 空 | 仅主人可查看的群号，逗号分隔 |

### 定位查询（v1.4.0 新增）

让 AI 能按**时间段 / 某人 / 关键词**查找消息，而不是只能取最近 N 条。

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `enable_locate` | switch | `true` | 定位功能总开关。关闭后完全等同旧版（只按条数取最近） |
| `enable_time_range` | switch | `true` | 允许 `since`/`until` 时间过滤 |
| `enable_user_filter` | switch | `true` | 允许 `user_id`（同时匹配 QQ 号、群名片、昵称） |
| `enable_keyword` | switch | `true` | 允许 `keyword` 关键词过滤 |
| `default_scan_limit` | integer | `300` | 不传 `scan_limit` 时往回扫多少条。300 ≈ 中群一天、大群十几分钟 |
| `max_scan_limit` | integer | `0` | 扫描条数硬上限。`0` = 按实现自适应（NapCat 2000 / LLOneBot 1200 / SnowLuma 800） |
| `scan_max_seconds` | integer | `25` | 单次定位的时间上限（秒），到点带着已扫结果返回 |
| `max_fetch_per_request` | integer | `50` | 每次向 OneBot 请求多少条（会被实现自身上限压低，如 LLOneBot ≤30） |
| `fetch_timeout_sec` | integer | `15` | 单次 OneBot 历史请求超时 |
| `max_scanned_per_turn` | integer | `3000` | 每回合累加扫描条数上限，防连续调用打爆服务器 |
| `max_calls_per_turn` | integer | `3` | 每回合允许调用 `get_history` 的总次数 |
| `max_calls_per_target_per_turn` | integer | `2` | 同一会话每回合最多查几次（定位需要翻页，故高于旧的隐式 1 次） |
| `early_stop_on_enough` | switch | `true` | 无 `since` 时命中够数即停；带 `since` 时始终扫到时间边界 |
| `detect_boundary` | switch | `true` | 识别「已到会话最早」并提前停止、在结果头标注 |
| `keyword_case_sensitive` | switch | `false` | 关键词是否区分大小写 |
| `max_keywords` | integer | `5` | 单次最多接受几个关键词 |
| `offset_max` | integer | `1000` | `offset` 上限 |
| `max_return_count` | integer | `80` | `count` 上限 |
| `locate_head_meta` | switch | `true` | 返回「命中/扫描/覆盖/到最早/耗时」元信息头。**建议保持开启** |
| `locate_fallback_on_error` | switch | `true` | 翻页途中锚点失效时自动从最新一页重新定位 |
| `locate_cache_ttl_sec` | integer | `120` | 完全相同的定位条件在此时间内直接返回缓存 |

## 输出格式

每条消息的发送者是 **`昵称(QQ)`**：

```
小明(10001): 我是卡片张三 (msg_id:1000)
张三(10002): 我是昵称张三 (msg_id:1001)
```

带 QQ 号不是装饰——**昵称和群名片都会变，而且两者经常不一致**。没有稳定的 ID，
模型无法判断两个名字指的是不是同一个人。

定位时最前面还有一行「涉及」，**按人（QQ）聚合**，昵称与群名片不同时并列显示：

```
涉及: 小明[群名片:张三](10001)、张三[群名片:李四](10002)、王五(10003)…（共8人）
```

上例中搜「张三」命中了两个人——第一个人**群名片**叫张三，第二个人**昵称**就叫张三。
超过 5 人时只列最活跃的 5 位，并注明总人数。

## 使用

跟 AI 说"总结某某群/某某人最近聊了些什么"即可。默认条数可在配置中调整，也可直接使用时说明。

定位用法举例：

- "昨天 9 点 10 分群里谁说过话？" → `since` / `until` 时间窗
- "张三昨天下午说了什么？" → `user_id` + 时间窗
- "群里最近有人提过部署吗？" → `keyword`
- 没找到时会返回「扫描范围内未命中（已扫最近 N 条，未到会话最早）」，可让 AI 加大 `scan_limit` 继续往前扫

> ⚠️ 定位是**从最新消息向更早翻页**再本地过滤，不是搜索索引：最近几百到几千条很快，
> 很久以前的消息可能够不着。返回头会明确告知实际扫了多少、覆盖多长时间、有没有扫到头。

## 附带的 KiraAI Skill：跨会话总结（summarize_other）

仓库里附带了一个 KiraAI 的 **Skill**（`summarize_other/`），让机器人学会"总结其他会话"这件事：

- **是什么**：KiraAI 的 Skills 系统（`data/skills/<名字>/SKILL.md`，YAML frontmatter 声明 `name` + `description`）会在系统提示里列出可用技能，AI 判断场景匹配后读取 SKILL.md 并照做。本 skill 就是教 AI：用户想总结某个群/某个人时，调 `get_history` 拿消息 → 提炼 40-120 字总结。
- **怎么装**：把 `summarize_other/` 文件夹复制到 KiraAI 的 `data/skills/` 下（即 `data/skills/summarize_other/SKILL.md`），然后在 WebUI 的 Skills 页面确认启用即可。
- **不用也无所谓**：这个 skill 只是"锦上添花"——它本质是给 AI 一段提示词。就算不装，AI 也能直接听懂"总结某某群最近聊了什么"并自己调用 `get_history` 工具；装了只是让 AI 更稳定地按固定格式总结（40-120 字、提炼核心观点、失败时礼貌告知）。你也可以自己改 `SKILL.md` 里的提示词，或者干脆让 AI 自己学会——工具本身才是核心，skill 只是使用姿势的模板。

## 工作原理

```
用户要求总结/查看历史
        ↓
get_history 工具被调用
        ↓
【不传定位参数】最近 N 条
1. WS 通道优先（复用适配器连接，ID 与 OneBot 层一致）
   → 失败自动降级 HTTP 通道（QQ 客户端数据库，数据更全）
2. 强解析（占位 raw_message → 段数组；reply 段 → [引用 msg_id:xxx]）
3. get_msg 批量刷新（最多 10 条/次）恢复媒体 URL
4. 过滤仍无法解析的空引用占位消息
5. 返回带 msg_id 的格式化文本

【传了 since/until/user_id/keyword】定位
1. 探测 OneBot 实现（get_version_info）→ 决定锚点字段与翻页方向
2. 从最新消息开始翻页，按条件本地过滤（每条条件都必须满足，AND 语义）
3. 停止条件：命中够数 / 到达 since 边界 / 到会话最早 / 扫描或时间上限
4. 附加元信息头 +「涉及」行（按 QQ 聚合，名片与昵称不同时并列显示）
5. 按 count 截断返回；未命中时说明扫描范围并建议加大 scan_limit
```

### 为什么是"翻页"而不是"搜索"

OneBot 协议**没有任何**按时间/关键词检索的接口（NapCat 内部的
`queryMsgsWithFilterEx` 并未暴露成 onebot action）。因此定位只能实现为
**从最新消息向更早翻页 + 本地过滤**，代价是：

| 查询类型 | 体验 |
|---|---|
| 最近几小时 / 最近几百条 | 快（命中够数就停） |
| 「昨天 9 点谁说过话」 | 好（有 `since` 就扫到边界为止） |
| 「某人最近说了什么」 | 好 |
| 「很久以前的关键词」 | 可能够不着（受 `scan_limit` 限制） |

三种实现的翻页能力不同，工具会**自动探测**并据此设置上限：

| 实现 | 锚点参数 | 扫描上限 | 限制 |
|---|---|---|---|
| NapCat | `message_seq` | 2000 | — |
| LLOneBot | `message_seq` | 1200 | 单次请求 ≤30 条 |
| SnowLuma | `message_id`（常为负） | 800 | 服务端强制 300ms 间隔 |

## 常见问题

**Q：为什么之前会显示 `[引用消息]`？**
A：这是 SnowLuma 的 reply 段转换失败时生成的 raw_message 占位（消息内容实际为空）。v1.3.0 起会自动过滤这类占位，改用真实段数组解析。

**Q：WS 和 HTTP 都开会不会冲突？**
A：不会。同一轮只走一个通道（WS 优先，失败才走 HTTP）。两者互补：WS 的 ID 与适配器一致（可被 get_msg/转发反查），HTTP 数据更全（含启动前消息）。

**Q：需要额外配置 WS 连接吗？**
A：不需要。WS 通道复用 KiraAI 框架已有的适配器连接，零配置。

**Q：定位查询会查多久？**
A：取决于条件。命中够数即停（默认几十条），带 `since` 时会一直扫到该时间点为止。
单次调用有 `scan_max_seconds`（默认 25 秒）上限，到点会带着已扫到的结果返回并说明。

**Q：为什么「命中=50+」有个加号？**
A：加号表示**下界**——扫描因为命中够数 / 条数上限 / 时间上限而提前停止了，
真实命中数可能更多。只有扫到会话最早或 `since` 边界时才会给出精确数字。

**Q：返回的「涉及」行为什么一个人会有两个名字？**
A：群里同一个人既有 QQ 昵称也有群名片，两者经常不同。按 QQ 聚合后并列显示为
`小明[群名片:张三](10001)`，这样搜「张三」命中两个不同的人时也能分清是哪个。
